# 크루 · 랜드마크 기획

> 상태: **Phase A·B·C 구현됨** — 확정 개발 순서 A→B→C  
> 목적: Phase별로 구현할 때 이 문서를 기준으로 한다.  
> 최종 정리: 2026-08-06  
> API 출처: [한국관광공사_국문 관광정보 서비스_GW](https://www.data.go.kr/data/15101578/openapi.do)

---

## 1. 배경과 방향

### 현재 (구현됨)

- 개인이 깃발을 꽂고, 개인끼리 상대 깃발을 점령한다.
- 깃발 cost: 100 / 300 / 500 / 1000
- 반경: cost별 100 / 150 / 200 / 300m (랜드마크 존 안은 5m)
- 점령 확률: 10 / 25 / 50 / 75%
- 전투력: 보유 active 깃발 cost 합
- 랜드마크: TourAPI·관리자 큐레이션, 존 안 개인 정복·개인 Top10/괄호 (Phase A·B)
- **크루(Phase C) 구현됨** (마이그레이션 `026_crews.sql` 적용 필요)

### 처음에 검토했다가 보류한 안

- 크루원이 같은 깃발에 포인트를 쌓아 키우고, 합동 점령(동참 알림·풀 모금·동시 재실)으로 뺏는 방식
- UX·실시간·어뷰징·지분 처리 부담이 커서 **1차로 채택하지 않음**

### 채택한 방향

1. **랜드마크(관광지 등)를 지도에 미리 둔다** — 쟁탈의 무대
2. 랜드마크 안에서는 **개인 깃발 꽂기·점령**만으로 싸운다 (합동 UX 없음)
3. **크루는 집계 단위** — 존 안 깃발 cost를 **개인과 크루에 이중 합산**해 명칭 권리·Top10에 사용

### 확정 개발 순서

이 순서로만 진행한다. 앞 Phase가 동작한 뒤에 다음 Phase로 넘어간다.

| Phase | 한 줄 | 완료 기준 |
|-------|--------|-----------|
| **A** ✅ | TourAPI 연동 → 관리자 큐레이션 → **지도에 랜드마크 표시** | 관리자가 가져온 장소를 노출 켜면 유저 지도에 존(200m)이 보인다 |
| **B** ✅ | 랜드마크 영역 안 **개인 깃발 꽂기·점령** (+ 개인 합산·괄호·Top10) | 존 안에서 5m 깃발로 싸우고, 개인 기준으로 명칭/Top10이 돌아간다 |
| **C** | **크루** (멤버십·이중 집계·탭·하이라이트·초대) | 크루 합산이 개인과 섞여 1위·Top10에 반영된다 |

합동 점령 등 §5.8 비범위는 위 세 Phase 밖에서 재기획한다.

## 2. 랜드마크

### 정의

- 지도에 미리 표시되는 고정 구역 (한국관광공사 TourAPI 동기화 및/또는 관리자 등록)
- 기본 영향 반경: **약 200m**
- 기존 `premium_places`(상점·쿠폰)와 **별도 엔티티**

### 표시

- 지도 마커 + 200m 범위
- 1위 주체가 있으면 이름 옆에 괄호 표기 (지하철역 스폰서 표기 느낌)
  - 개인 1위: 닉네임
  - 크루 1위: **크루명** (개인 닉네임과 같은 텍스트 표기 방식. 프로필 이미지 배지 없음)
- 선택 시 정보 영역: 기본 정보 + **합산 전투력 Top10** (개인·크루 혼합)

### 운영 상태 (폐역)

- 랜드마크는 **삭제하지 않는다**
- 의미가 없어지면 **폐역(비활성)** 처리
- 폐역 시:
  - 상세 설명에 **「현재 운영되지 않는 랜드마크」** 안내
  - **깃발 꽂기·점령·집계·명칭·Top10은 그대로 유지** (규칙 엔진을 끄지 않음)
- 삭제·반경 복귀 기획은 없음

### 데이터 출처

- 상세는 **§6 TourAPI 활용 설계** 참고
- 관리자: 후보 적재 → 지도 노출/폐역 → 반경 오버라이드·수동 추가

## 3. 랜드마크 안 깃발 규칙

| 항목 | 규칙 |
|------|------|
| cost | 기존과 동일 (100 / 300 / 500 / 1000) |
| 반경 | **항상 5m** (cost별 대형 반경 사용 안 함) |
| 개수 | 유저당 개수 제한 없음. **5m 충돌만** 준수하면 여러 개 가능 |
| 소속 판정 | 깃발 **중심 좌표**가 랜드마크 200m 안이면 해당 랜드마크 소속. **반경이 겹치면 모든 해당 랜드마크에 동시 적용** |
| 외부 깃발과의 충돌 | 랜드마크 **밖** 일반 깃발의 큰 반경이 존 **안** 배치를 막지 않음 |
| 존 안 신규 | 항상 랜드마크형(5m) |
| 점령 | 기존 개인 점령 규칙과 동일 (확률·비용·방어 보상) |

### 랜드마크 지도 노출 ON 시 기존 깃발 편입

- 관리자가 **지도 노출을 켤 때**, 중심이 존 반경 안인 기존 깃발은 **반경을 5m로 줄여 편입**하고 합산에 포함한다
- 편입 후 5m 기준으로 드물게 겹치더라도 **기존 깃발은 유지** (신규만 5m 규칙 적용)
- 폐역·노출 OFF로 반경을 다시 키우지 않음 → 복귀·겹침 폭발 문제 없음

### 현행 충돌 로직과의 관계

- 현재 `findActivePinsNear`는 기존·신규 반경 중 큰 값으로 충돌한다
- 랜드마크 존 안 배치는 **존 안 깃발끼리 5m 기준**으로만 충돌 검사하고, **존 밖 깃발 반경은 무시**해야 한다

## 4. 합산 · 명칭 권리 · Top10

### 집계 단위

- 대상: 해당 랜드마크 존 안 **active** 깃발
- **모든 유저**의 깃발 → **개인 버킷**에 cost 합산 (미소속·소속 공통)
- 크루 소속 유저의 깃발 → **추가로 그 크루 버킷**에도 cost 합산 (**이중 집계**)
- Top10: **개인·크루 혼합** 주체 순위 (같은 유저가 개인으로, 소속 크루가 크루로 동시에 올라갈 수 있음)
- 반영: **실시간** (꽂기 / 점령 / 삭제 / 가입 승인 / 탈퇴·추방 / 해산 등 성공 직후)

### 소속 변경과 집계

- **가입(승인) 순간**: 해당 유저의 존 안 active 깃발 cost가 크루 버킷에 **즉시 합산**
- **탈퇴·추방**: 크루 버킷에서 **즉시 제외**. 깃발은 개인 버킷에만 남음
- **해산**: 크루 버킷·크루 랭킹 항목 제거. 멤버 깃발은 전부 **개인만** 집계
- 깃발에 생성 시점 `crew_id` 스냅샷을 두지 않는다. **현재 멤버십** 기준으로 집계한다

### 명칭 (괄호) 1위

- 합산 전투력 1위 주체를 랜드마크명 옆에 표시
- 개인이면 **닉네임**, 크루이면 **크루명** (동일 텍스트 스타일)
- **동점**이면 개인/크루 구분 없이 **해당 점수에 먼저 도달한 주체**
  - 정의: 그 주체의 합산이 현재 1위 점수에 **처음 도달한 시각**이 더 이른 쪽
  - 점수가 깨졌다가 다시 동점이 되면 **다시 도달한 시각** 기준

### 닉네임 · 크루명

- 개인 1위·Top10 개인 항목은 **닉네임** 표시
- 크루 1위·Top10 크루 항목은 **크루명** 표시
- 비속어는 **닉네임 설정 시** 차단 (구현됨). 크루명은 **비속어 차단 · 최대 10자** (§5.2)

### 미운영(폐역) 랜드마크

- `is_closed`여도 `map_visible`이면 지도 노출·괄호·Top10·집계 **유지** (기존 Phase A/B와 동일)
- 노출 OFF(`map_visible=false`)면 지도에서만 숨김. 이미 쌓인 점수 규칙은 Phase B와 동일

### 크루 (랜드마크 단계에서의 역할)

- 크루는 “합동 점령 주체”가 아니라 **집계·표시 단위**
- 상세 규칙은 **§5**

## 5. 크루 (Phase C — 확정 규칙)

Phase A·B가 동작한 뒤 구현한다. 아래는 **2026-08-06 확정**. 남은 미결은 §5.11.

### 5.1 멤버십 · 권한

| 항목 | 규칙 |
|------|------|
| 소속 | **1인 1크루** (미소속 ↔ 소속 1개만) |
| 가입 | **신청 → 리더 승인** 후 정식 멤버 (초대 링크도 동일) |
| 신청 제한 | **대기 중 신청은 전역 1건만**. 이미 소속이면 신청 불가 |
| 정원 | 현재 인원 ≥ 상한이면 **신규 신청 불가**. 이미 대기 중인 신청은 **자동 거절하지 않음** (탈퇴·추방으로 자리가 나면 리더가 승인 가능). 승인 시점에 정원이 가득하면 그 승인만 거부 |
| 생성 | **누구나** 생성 가능. 비용 **1000P** 차감(실패 시 롤백). 생성자는 리더 |
| 크루명 | **active 크루 간 중복 불가**, **최대 10자**, **비속어 차단**. 변경·해산 후 옛 이름 **재사용 가능** (§5.9) |
| 인원 상한 | 리더가 설정. **최소 2 · 최대 20** (생성 직후 리더 1명이므로 상한은 최소 2부터) |
| 리더 권한 | 가입 승인/거절, **추방**, **해산**, **리더 위임**, 인원 상한·소개·활동지역 변경 |
| 리더 탈퇴 | **위임 필수** 후 일반 멤버로 탈퇴 가능. **혼자(본인만)일 때는 해산** |
| 멤버 | 자발적 **탈퇴** 가능 |

### 5.2 크루 프로필 필드

| 필드 | 규칙 |
|------|------|
| 이름 | 필수, **현재 존재하는 크루 간** 유니크, 최대 10자, 비속어 차단. **이름 변경·해산 후 옛 이름은 다른 크루가 재사용 가능** |
| 소개 | 생성 시·이후 작성 가능 (선택) |
| 활동지역 | **1개만** 선택. 값 = `TOUR_AREA_OPTIONS`(서울·인천·…·제주) + **`전국`**. 검색 필터에 사용 |
| 인원 상한 | 리더 설정, **2~20** |
| 프로필 이미지 | **선택**. 1차부터 지원. 스펙은 §5.10. 목록/상세·크루 탭에 표시. 랜드마크 괄호(1위)에는 텍스트(크루명)만 |

### 5.3 집계 (개인 ↔ 크루)

**전역**

- **개인 전투력**: 보유 **active** 깃발 cost 합 (일반 깃발 + 랜드마크 존 깃발)
- **크루 전투력**: 소속 멤버들의 **개인 전투력 합**

**랜드마크별 (명칭·Top10)**

- **개인 순위**: 그 유저가 해당 랜드마크 존 안에 꽂은 active 깃발 **cost 합**
- **크루 순위**: 소속 멤버들이 해당 랜드마크 존 안에 꽂은 active 깃발 **cost 합** (이중 집계 — 개인 순위에도 그대로 남음)
- 가입 승인 시 크루 버킷에 즉시 합산, 탈퇴·추방·해산 시 크루 버킷에서 제외

**크루 탭 부가 지표**

| 지표 | 정의 |
|------|------|
| **기여 포인트** | 해당 멤버가 크루 버킷에 넣어서 합산되는 본인 cost (소속 중 active 깃발 cost 합 = 그 멤버의 개인 전투력과 동일하게 읽힘). 멤버별 “크루에 기여한 양” 표시용 |
| **랜드마크 공략** | 해당 멤버가 존 안에 active 깃발을 **1개 이상** 가진 랜드마크 수 (1차 정의) |

### 5.4 하단 네비 · 크루 탭 · 랭킹

하단 탭: **지도 / 랭킹 / 크루 / 마이** (4탭)

**랭킹 탭**

- 기존 개인 랭킹(전투력 등) 유지
- **크루별 랭킹** 추가 (크루 전투력 = 멤버 개인 전투력 합)

**크루 탭**

- 미소속: 크루 검색·목록 (활동지역 필터: `TOUR_AREA_OPTIONS` + 전국) → 신청 / 생성(1000P)
- 소속: 소속 크루 현황
  - 인원, 멤버 목록
  - **크루 내 랭킹**: 멤버별 **개인 전투력** 순
  - **부가 표시**: 랜드마크 공략 수, 기여 포인트 (§5.3)
  - 리더 UI: 승인 대기, 추방, 위임, 해산, 설정

### 5.5 지도 레이어 · 하이라이트

레이어 토글 순서:

| 순서 | 레이어 | 동작 |
|------|--------|------|
| 1 | 랜드마크 | 기존과 동일 |
| 2 | 깃발 | 기존과 동일 (전체 사용자 깃발) |
| 3 | **크루** | ON 시 **모든 크루 소속 유저의 깃발** 하이라이트 |
| 4 | 프리미엄 | 기존과 동일 |

- **내 크루만**: 레이어 토글과 **별도 칩**. ON이면 내 소속 크루 멤버 깃발만 하이라이트 (크루 레이어와 함께 쓰는 UX)
- 미소속이면 「내 크루만」칩 비활성 또는 안내

### 5.6 초대 링크

- 크루마다 **영구** 초대 링크 1개 (해산 전까지 유효)
- 링크로 진입 → **크루 소개**(이름·소개·활동지역·인원 등) 표시
- **가입 신청** → 리더 **승인** (일반 신청과 동일). 비로그인이면 로그인 후 신청
- 이미 소속·대기 신청 있음·정원 가득이면 **신규** 신청 불가 (§5.1). 대기 중 신청은 정원 변화와 무관하게 유지

### 5.7 관리자

- 메뉴: **크루 관리** (`/admin/crews` 가칭)
- **목록**: 이름, 활동지역, 인원, 리더, 생성일 등
- **상세**: 크루 정보 + **크루원 목록** (역할, 전투력/기여 등)
- **수정**: 관리자가 크루 정보(이름·소개·활동지역·인원 상한·이미지 등) 변경 가능 (유저 요청 대응)
- **강제 해산**: 1차에 기능 준비 (운영용)

### 5.8 명시적 비범위 · 후순위

**1차에서 하지 않음**

- 크루원이 한 깃발에 포인트를 함께 쌓아 키우기
- 합동 점령 (개시·동참 알림·풀 모금·동시 재실)
- 크루 전용 깃발 소유로 개인 깃발을 대체하는 모델
- 랜드마크 괄호에 크루 프로필 이미지 배지 (괄호는 크루명 텍스트만)

**앱 출시 후**

- 가입 **승인/거절 푸시·인앱 알림** — 웹 단계에서는 알림 인프라 없음. 앱 구현 시 신청자·리더에게 발송

### 5.9 크루명 유니크 · 재사용

- 유니크 범위: **해산되지 않은(active) 크루의 현재 이름**만
- 해산하면 그 이름은 즉시 재사용 가능
- 리더/관리자가 **이름을 바꾸면** 이전 이름도 재사용 가능
- 내부 식별은 항상 `crew.id`(UUID). 초대 링크·집계·히스토리는 id 기준이라 이름 변경과 무관

**의도적 허용 리스크 (문제로 보지 않음, 인지만)**

- 유명 크루가 이름을 바꾸면 다른 사람이 옛 이름으로 새 크루를 만들 수 있음(사칭 느낌)
- 완화(후순위): 신고·관리자 강제 이름 변경, 필요 시 최근 사용 이름 쿨다운 등. **1차는 쿨다운 없음**

### 5.10 크루 프로필 이미지 스펙 (확정)

유저 아바타(`lib/avatar.ts`, `AVATAR_MAX_BYTES`)와 **동일 계열**로 맞춘다. DB bytea 저장 전제.

| 항목 | 값 |
|------|-----|
| 출력 크기 | **256×256** (정사각 크롭) |
| 포맷 | **WebP** 우선, 실패/용량 초과 시 **JPEG** |
| 서버 허용 MIME | `image/webp`, `image/jpeg`, `image/png`(업로드 원본) → 저장은 webp/jpeg |
| **최대 용량** | **50KB** (`AVATAR_MAX_BYTES`와 동일) |
| UI | 선택 사항. 미설정 시 기본 플레이스홀더 |

구현 시 클라이언트 압축은 기존 `compressAvatarFile` 재사용 또는 동일 상수로 공유한다.

### 5.11 구현 전 남은 미결

| # | 항목 | 메모 |
|---|------|------|
| 1 | **승인 시 정원 카피** | 대기 유지 확정. 승인 클릭 시 가득하면 그 승인만 실패 |

**생성 1000P 차감·실패 롤백**은 확정.

### 6.5 핵심 원칙: API ≠ 지도 직행

```
TourAPI (후보 소스)
    ↓ 관리자 검색 / 지역 가져오기
landmarks 테이블 (전체 카탈로그, 기본 map_visible=false)
    ↓ 관리자가 「지도 노출」 ON
유저 지도 API (map_visible=true 만)
```

- 유저 앱은 **우리 DB만** 읽는다. TourAPI 키·쿼터를 클라이언트에 노출하지 않는다.
- 전국 26만 건을 한 번에 넣지 않는다. **지역·키워드로 가져와 큐레이션**한다.
- `premium_places`와 테이블·메뉴를 분리한다 (광고/쿠폰 vs 쟁탈 존).

말씀하신 **「관리자에 API 데이터를 뿌리고 → 지도 노출 여부 결정」** 흐름과 일치한다.

### 6.6 관리자 「랜드마크 관리」 IA

프리미엄 장소 관리와 같은 패턴 (`AdminShell` 콘텐츠관리 메뉴 추가).

**메뉴:** `/admin/landmarks`

**목록 필터**

1. **지도 노출 중** — `map_visible=true`
2. **카탈로그** — DB에 있으나 미노출
3. **폐역** — `is_closed=true`
4. 검색: 이름, 지역코드, contentType, Tour contentId

**주요 액션**

| 액션 | 동작 |
|------|------|
| TourAPI에서 가져오기 | 지역(`areaBasedList2`) 또는 키워드/위치 검색 → 후보 upsert (`map_visible` 기본 false) |
| 지도 노출 ON | `map_visible=true`. **최초 ON 시** 존 안 기존 깃발 5m 편입(§3) — Phase B |
| 지도 노출 OFF | `map_visible=false` (마커 숨김). 이미 편입된 깃발 반경은 되돌리지 않음 |
| 폐역 | `is_closed=true` + 안내 문구. 꽂기/점령/집계는 유지(§2) |
| 수동 추가 | `source=manual`, 지도에서 좌표 지정 (`AdminLocationMap` 재사용) |
| 반경 수정 | `radius_meters` 오버라이드 (기본 200) |
| 상세 새로고침 | `detailCommon2`로 overview/주소/이미지 갱신 |

**노출 OFF vs 폐역**

| | 지도 노출 OFF | 폐역 |
|--|---------------|------|
| 맵 마커 | 숨김 | `map_visible`이면 **표시** + 상세에 폐역 안내 |
| 게임 규칙 | (마커 없으니 사실상 신규 유입 없음) | 꽂기·점령·집계 **유지** |
| 용도 | 아직/더 이상 무대가 아님 | “운영 종료” 카피만 |

1차: 폐역이어도 `map_visible`이면 맵에 남긴다. 폐역=자동 숨김은 하지 않는다.

### 6.7 유저 지도 (Phase A 범위)

**Phase A에서 할 것**

- [ ] `landmarks` 스키마 + 마이그레이션
- [ ] 서버 TourAPI 클라이언트 (`TOUR_API_SERVICE_KEY`는 서버 전용)
- [ ] 관리자 랜드마크 메뉴 (가져오기 / 노출 / 폐역 / 수동 추가)
- [ ] 유저 `GET` 랜드마크 목록 (bbox 또는 근처, `map_visible=true`)
- [ ] 지도 마커 + 200m 원 + 탭 시 이름·주소·개요·이미지
- [ ] 폐역 시 상세 안내 문구
- [ ] 출처 고지 (한국관광공사)

**Phase A에서 하지 않는 것**

- 존 안 5m 깃발·충돌 예외·편입 (Phase B)
- 합산·괄호 명칭·Top10 (Phase B)
- 크루 (Phase C)

괄호 자리(`남산타워 (○○크루)`)는 UI 여백만 두거나, Phase B 전까지는 이름만 표시.

### 6.8 크루 시스템과의 연계 (데이터·화면 계약)

크루는 나중에 붙이되, **지금 만드는 랜드마크 모델이 계약**이 된다.

```
landmark (고정 무대, TourAPI/수동)
  └── pins whose center ∈ radius   ← Phase B
        └── owner → crew_id?       ← Phase C
              └── SUM(cost) by crew|user → title holder + Top10
```

| 이후 기능 | 지금 준비할 것 | 나중에 붙일 것 |
|-----------|----------------|----------------|
| 괄호 1위 | `landmarks.name`, 안정적 `id` | 실시간 집계 또는 holder 캐시 필드 |
| Top10 시트 | 랜드마크 상세 바텀시트 골격 | `/api/landmarks/[id]/ranking` |
| 크루 표시 | 괄호·Top10에 닉네임 텍스트 슬롯 | 크루명 텍스트 (이미지 배지 없음) |
| 지도 하이라이트 | 레이어 토글 3칸 | 4칸(랜드마크/깃발/**크루**/프리미엄) + **내 크루만** 별도 칩 |
| 편입 | `map_visible` false→true 전환 훅 | 구현됨 (Phase B) |

**관리자 「지도 노출 ON」이 게임 무대 오픈 스위치**다.  
개인 이중 집계 위에 `crew` 버킷을 얹으면 Phase C 집계가 성립한다. 멤버십은 **현재 소속** 기준이다.

### 6.9 환경·운영 메모

- `.env.local`: `TOUR_API_SERVICE_KEY` (data.go.kr 발급 키). `NEXT_PUBLIC_` 금지.
- `MobileApp`: 서비스명(`이땅내땅` 등) 고정.
- 개발 트래픽 한도: 관리자 “가져오기”만 TourAPI 호출, 이후는 DB.
- 외부 이미지 도메인: `next.config` 허용 여부 확인.
